# relations/：小さい元の関係式による単項性の証明

PARI の類群計算（`bnfinit`、`bnfisprincipal`）を使わずに、$k_{p^n}$（$p$ は奇素数）で完全分解する素数の上の素イデアルが単項であることを示す。

## 考え方

- 元は $\alpha=c+\sum_i a_i\eta_i$ と書く。$\eta_i$（$i$ は $p^n$ を法とする）は Gauss 周期で、$\mathrm{Gal}(k_{p^n}/\mathbb{Q})$ の生成元は $\eta_i\mapsto\eta_{i+1}$。
- **行**：完全分解する素数 $q$、元 $\alpha$、$|N(\alpha)|$ の素因数分解の組。$q$ がノルムをちょうど 1 回割り、他の素因数 $r$ がすべて次のどれかなら、$q$ の上の素イデアルは単項である。
  - $r=p$（$p$ の上の素イデアルは単項）
  - $r$ は完全分解しない（真部分体の類数が 1 なら、$r$ の上の素イデアルは単項）
  - $r$ は完全分解し、その上の素イデアルが単項であることが先に示されている
- **範囲の形式**：区間 $[A,B)$ の完全分解素数 $q$ すべてに、「他の完全分解する素因数は $q$ より小さい」という行を与える。$A$ 未満がすべて済んでいれば、$q$ についての帰納法で $B$ 未満がすべて単項になる。区間ごとに独立に計算と検証ができる。
- **格子ブロック**：最小の完全分解素数がほとんどのノルムを割る場合（$k_{7^2}$ の 19）に使う。ノルムが $p^aq_0^k$ で、$q_0$ の上の相異なる $k$ 個の素イデアルにちょうど 1 回ずつ入る元を集める。その共役すべての 0/1 ベクトルが $\mathbb{Z}^N$ を張れば、$q_0$ の上の素イデアルは単項。

## プログラム

| ファイル | 役割 | 信頼 |
|---|---|---|
| `verify.py` | 検証器。ノルムは補助素数での計算と中国剰余定理で厳密に求める。素数性は証明つきの判定。上界は区間演算 | 信頼する側。python-flint のみ使用 |
| `aggregate.py` | 最後の段階。区間が 0 から隙間なく続くことを確かめ、完全分解素数の一覧と素数についての和を**自分で計算し直して**、類数の上界を出す。要約（`summary_A_B.json`）から使うのは「その区間が `verify.py` に合格した」という事実だけ | 信頼する側 |
| `check_recheck.py` | 全行の再検証（`recheck.yml`）の結果が、すべての範囲ファイルについて揃っているかを確かめる | 信頼する側 |
| `subfields.py` | 真部分体 $k_{p^j}$（$j<n$）の類数が 1 であることを、素数を使わない Miller の補題、階数定理、岩澤の定理だけで確かめる | 信頼する側 |
| `field.py`、`collect.py`、`search.py`、`export.py`、`gen_range.py` | 行の探索（無作為な小さい元、素数ごとの格子の簡約）。ノルムは固定小数点、因数分解は PARI | 信頼しない。出力は `verify.py` が確かめる |
| `need_k81.py` | $k_{3^4}$ に必要な範囲の見積もり（浮動小数） | 見積もり用 |

## 結果

### $k_{7^2}$：既存の証明と独立な 2 つ目の証明書

- `cert_k7_2.txt`（2.4 MB、29,834 行と 19 の格子ブロック）。$2.2\cdot10^7$ 以下の完全分解素数 28,381 個すべてを含む。
- `python3 verify.py cert_k7_2.txt` は約 9 秒で、$c=80$ のとき $h<152.0639<197$。
- 探索は 2 コアで約 20 分（PARI による以前の方法は約 100 コア時間、証明書は 187 MB）。

### $k_{3^4}$：全区間の検証が合格、監査済み（2026-11-24）

$k_{3^4}=\mathbb{Q}(\zeta_{243})^+$（導手 243 の実円分体）。GRH 下では van der Linden (1982) による。無条件の証明は、MathSciNet での被引用文献とキーワードの検索を含め、確認した範囲では見つかっていない（`docs/literature.md`）。

- 対象：$q\equiv\pm1 \pmod{243}$ の素数（$k_{3^4}$ で完全分解する素数）のうち $3\cdot10^{10}$ 未満のもの、16,049,777 個。そのすべてに、検証を通った行がある。
- 構成：`k3_4/base_cert.txt`（$10^7$ 未満、一般の形式）と、$[10^7,3\cdot10^{10})$ を覆う 82 個の区間（範囲の形式、GitHub Actions で生成し、その場で `verify.py` が検証）。要約は `k3_4/summary_A_B.json`、行の本体は GitHub のリリース `k3_4-rows-45339096699` と `k3_4-rows-45339615023`（計 約 490 MB、チェックサムは `k3_4/rows_A_B.sha256`）。
- `python3 aggregate.py k3_4` の出力（`k3_4/aggregate_output.txt`。和は要約の値を使わず計算し直したもの）：

| $c$ | 積分 $\le$ | 素数についての和 $\ge$ | $B\ge$ | $h<$ |
|---|---|---|---|---|
| 60 | 1.2660224223 | 0.8355826772 | 0.0047699 | 550.5021 |
| 80 | 1.2651137825 | 0.8611113518 | 0.0312072 | 112.1901 |
| 100 | 1.2646927462 | 0.8733014006 | 0.0438183 | **99.8767** |
| 150 | 1.2642766179 | 0.8855807997 | 0.0565138 | 116.1599 |
| 200 | 1.2641309048 | 0.8899359318 | 0.0610147 | 143.4550 |

- 階数定理の閾値は 163（$\ell=163\equiv1 \bmod 81$）。$h<99.8767<163$。
- 結論に必要な残りの入力：Miller の補題（J. Number Theory 2015 の Lemma 1）、階数定理の一般形（van der Linden 1982 の Theorems 6, 8）、岩澤の定理（$3\nmid h$）。
- 真部分体の類数：$h(k_3)=h(k_{3^2})=h(k_{3^3})=1$ は文献に頼らずに出る。`python3 subfields.py 3 4` の出力は、素数を使わない Miller の補題で $h(k_3)<1.3455$、$h(k_{3^2})<1.3314$、$h(k_{3^3})<5.9601$。階数定理の閾値はそれぞれ 4、19、109。文献では van der Linden (1982) の Theorem 1（素数冪導手 $q$ で $\varphi(q)\le66$ なら類数 1、無条件）に含まれる（原論文で確認）。Miller の表が $k_{3^3}$ の典拠を Masley (1978) としているのは誤記で、Masley が示したのは素数冪導手 70 未満の場合。
- 確認したこと：完全分解素数の個数 16,049,777 は、検証器とは別の篩による数え上げと一致。和の値は浮動小数での事前の見積もり（$B=0.0438$）と一致。リリースから区間 $[24377625000,24752450000)$ を取り出し、チェックサムの一致と、手元での再検証（193,133 行、同じ要約）を確認。
- 計算量：80 ジョブ、各 16〜41 分（4 コア）。全体で約 2 時間。

### 監査（`docs/audit_relations.md`）

独立した監査で、証明を壊す誤りは見つからなかった。監査者は `verify.py` を使わない自作のコードで、上界 $h<99.8767$、完全分解素数の個数と和、積分、基礎証明書の全行、範囲ファイル 7 個（全行 2 個、標本 5 個）を確かめた。指摘 4 点への対応：

1. $h(k_{3^3})=1$ の典拠 → `subfields.py` で自己完結させた（上記）。
2. `aggregate.py` が要約の数値を信頼していた → 個数と和を計算し直すように変更。和を改竄した要約、個数の合わない要約、$A\ge B$ の区間は失敗する。
3. ワークフロー → `pipefail` を付け、python-flint を 0.9.0 に固定し、失敗したジョブの要約はアップロードしないようにした。要約に実行の番号と `verify.py` の sha256 を記録する。
4. 丸めが浮動小数を経由していた → `up`、`down` を整数演算に変更。要約の和は 10 進文字列で書く。

### 全行の再検証と再監査（2026-11-24）

- **全行の再検証。** 公開した 82 個の範囲ファイルすべてを、GitHub Actions（実行 45380165270）で 2 通りに検証し直した。1 つは `audit/relations_recheck.py`（`verify.py` を使わず、ノルムは PARI の終結式、素数性は PARI の `isprime`）、もう 1 つは修正後の `verify.py`。結果は `k3_4/recheck/`。`python3 check_recheck.py k3_4` の出力：82 個すべてで両方が合格、16,041,617 行、完全分解素数 16,041,617 個、チェックサムも一致。基礎部分の 8,160 個と合わせて 16,049,777 個。
- **再監査（`docs/audit_relations_2.md`）。** 修正後の `verify.py`、`aggregate.py`、`subfields.py`、`relations_recheck.py` に、証明を壊す誤りは見つからなかった。指摘 7 点（ワークフローの見逃し、終了コードなど）は対応済み。

**残っている信頼。**
- 要約（`summary_A_B.json`）から結論に効くのは、体、範囲、「その区間が合格した」という事実の 3 つ。合格の事実は、上の再検証の結果（`k3_4/recheck/`）と、公開した行に対して誰でも `verify.py --range` を実行し直せることで支えられている。
- 2 つの検証プログラムはコードとしては独立だが、書いたのは同じ作業者（Claude）。監査者（別のエージェント）は 1 回目の監査で自作のコードを使い、範囲ファイル 2 個の全行と基礎証明書の全行を確かめている。
- 文献：Miller の補題、階数定理、岩澤の定理。ソフトウェア：FLINT / Arb と PARI。
- 人による確認はまだ受けていない。

## 使い方

```sh
pip install python-flint cypari2 mpmath
python3 verify.py cert_k7_2.txt                                   # k_{7^2} の検証
python3 verify.py k3_4/base_cert.txt --complete 10000000          # k_{3^4} の基礎部分
python3 gen_range.py 3 4 A B rows.txt 4 && python3 verify.py rows.txt --range A B
python3 subfields.py 3 4                                          # 真部分体の類数 1
python3 aggregate.py k3_4 2 3 4 30000000000                       # 最後の段階（2 コアで約 2.5 分）。体と終点を指定
python3 check_recheck.py k3_4                                     # 全行の再検証の結果が揃っているか
```
